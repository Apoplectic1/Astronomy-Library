## Architectural conventions

These are baked into the public API and must be respected when adding code:

- **Hemisphere convention.** `Latitude`, `Longitude`, and `Declination` are stored as **non-negative magnitudes**, with direction in companion bool flags (`Location.North` / `Location.West` / `Target.North`). Constructors normalize by **XOR, not override**: a negative magnitude is flipped positive *and* the companion flag is inverted, so `new Target(declination: -5.0, north: false)` stores `Declination = 5.0, North = true` — i.e. **+5° North**, not −5° South. (Sign "wins" only when the caller passed the positive-hemisphere flag; the two inputs compose rather than one taking precedence.) Internal math reconstructs signed values just before feeding geometry. **Caller-side corollary — a silent-wrong-result trap for every bridge/adapter:** a caller holding an *already-signed* declination passes the **sign alone** and leaves the companion flag at its positive default; supplying both a negative magnitude *and* a pre-derived southern flag double-flips into the opposite hemisphere, compiling cleanly and failing only on southern input (pinned precedent: the early `ReportToTargetAdapter` test, `CHANGELOG.md` § 2026-05-18 Phase B).
- **RA is decimal hours in `[0, 24)`**, not degrees. Declination is decimal degrees.
- **The `AltAz` / `TargetGeometry` altitude is unrefracted** — degrees above the mathematical horizon. This is a convention of the *geometric* primitives, not a library-wide guarantee: `Astrometry.Refraction.SaemundssonDeg` is public, and refracted altitude is a first-class output elsewhere (`Session.AltAzSample.AltDegApparent`, and the apparent-altitude paths in `AltitudeCurve`, `MoonEphemeris`, `SunPosition`, `SkyBrightness`). When adding a refraction term, be explicit about which of the two you are producing and coordinate across `AltAz`, `TargetGeometry`, `RiseSet`.
- **Azimuth** is degrees from North, clockwise, in `[0, 360)` — **half-open**. Due north is the seam: the `cosAz` clamp forces exactly `1.0` for a target north of the zenith, `Acos(1.0)` is exactly `0.0`, and the eastern-half flip computes `360.0 - 0.0`, so `AzimuthAtHourAngle` folds `>= 360.0` back to `0.0`. Nothing downstream renormalizes (`AltAz`'s ctor stores verbatim), so the fold has to happen at the source.
- **DateTime kinds — UTC is a hard contract, enforced centrally.** `Astronomy.Core.Time.JulianDate.FromUtc` is the single gate: every time-based primitive funnels through it (`SiderealTime.Local` routes there; normalizing callers arrive as `FromUtc(AsUtc(x))`), and it **throws `ArgumentException` on a non-`Utc` `Kind`** rather than reinterpreting. The reason is that `DateTime.ToOADate()` ignores `Kind` entirely and reads raw ticks, so a `Local`/`Unspecified` instant would be silently reinterpreted as UTC and return an answer wrong by the caller's UTC offset. Because the gate is central, no downstream primitive needs its own guard.
  - `TimeKindGuard.AsUtc(DateTime)` (internal) remains the **converting** sibling for entry points that accept a local-frame instant (`AstroUtil`, `MoonEphemeris`, `NightCalculator`, `Sun/*`): `Local`/`Unspecified` are treated as local and converted via the machine zone; `Utc` is a no-op. Converting entry points therefore still accept any `Kind`; everything else requires `Utc`.
  - `NightWindow` outputs are `Kind=Utc`. The recommended consumer-facing carrier is `Astronomy.Core.Time.ObservationMoment` (record struct, `(Utc, Zone)`) — build via `FromLocal(local, zone)` or `Now(zone)` and pass `.Utc` to math helpers.
  - `LunarAge.DaysAt` predates the central gate and throws on its own; it is now consistent with the gate rather than an exception to a lenient rule.
- **Immutability + `With(...)`.** `Location` and `Target` are immutable; mutations produce new instances via a `With` method that takes optional parameters.
- **Rotation is represented two ways, and the difference is load-bearing.** `Astronomy.NINA.Target.RotationDeg` is a **non-nullable** double the ctor wraps into `[0, 360)` (default 0.0) — absence is inexpressible there and 0° reads as a real angle — whereas the Catalog plane's rotation is **nullable**, `null` meaning "the target expresses none", and the framing rules skip the rotation term for it. Any bridge between the two planes must map absence explicitly rather than defaulting to 0 (goes live at Phase D's `InputTargetAdapter` — `ROADMAP.md`).
- **Rename on meaning change; reshape only when meaning is stable.** When a type's *meaning* changes (not just its signature), rename it outright — the constellation-wide compile break is the point, forcing every stale mental model to be re-read rather than silently reinterpreted (decided at `openspec/changes/archive/2026-07-24-ks-dmag-moon-gate/design.md` § D2; same instinct as `CadenceSafe` → `Clears` and `FilterKind`'s outright deletion). Reshape-in-place is reserved for changes where meaning is stable and only the shape moves (the in-place evolution policy itself: `CONSUMERS.md` preamble).
- **Efficiency bar: allocate once per stage, and no speculative machinery.** Buffer-shaped APIs are plain `byte[]`/array surfaces sized and allocated once per stage with no gratuitous intermediate copies — but no `Span`/pooling/streaming machinery until a profile demands it; correctness and interop dominate (decided at `openspec/changes/archive/2026-08-06-xisf-codecs-and-image-read/design.md` § Goals; it shaped the codec layer's block-at-a-time surface).
- **Canonical singletons are `public static readonly` fields**, never expression-bodied `=> new T(...)` properties (swept library-wide 2026-05-27; `Target.Default`, `Location.Default`, the `Filter.H`…`B` presets, `MoonLimitProfile.Disabled`/`Narrowband`/`Broadband`). The owning types are immutable, so one shared instance is safe and there is zero per-access allocation on cold paths — but the load-bearing part is that **callers may rely on reference identity**: a consumer caching on these keys can compare with `ReferenceEquals` (TP's `ChartCacheStore` keys four cache axes that way). Re-introducing a factory property would silently break those callers rather than fail to compile.
- **D/M/S accessors are computed on read**, never stored. Don't add stored DMS fields — they would drift.
- **Missing XML docs on public members are a build error, not a warning**, in four of the nine shipped managed assemblies: `Astronomy.Core`, `.NINA`, `.PCL`, `.XISF` each set `<WarningsAsErrors>$(WarningsAsErrors);CS1591</WarningsAsErrors>`. The rest opt out deliberately, with the rationale in each csproj: `Astronomy.Catalog` (`NoWarn;CS1591` — the schema POCOs sit 1:1 with the documented SQL, so per-column docs would be noise) and the four Diagnostics-stack assemblies (`NoWarn;CS1591`, core/`.Windows`/`.WinUI` also `CA1031` — the severity members are self-describing; best-effort swallow-alls are the diagnostics contract). Adding a public member to an enforcing assembly without a `///` doc fails the build on the first compile.
- **`Location` is the site, not the session.** Carries geography (lat/lon/elev/TZ), atmospheric (Bortle/ExtinctionK), and terrain (`LocalHorizon: IHorizonProfile`). It does NOT carry an observation moment, a target floor, or a minimum duration — those are per-session inputs that consumers thread explicitly. As of 2026-05-18 (Phase 2 of the Location refactor), the previously `[Obsolete]` `Horizon`/`Duration` scalars and the `DateTime` field have been removed entirely. Scheduling helpers (`BestSession.For` / `ResolveCandidates` / `SessionSolvers`, `NightCalculator.ComputeNight(location, utc)`, `AltAzCalculator.At(target, location, utc)`) take all per-session inputs as explicit parameters.

## Thread safety

`Astronomy.Core` is **thread-safe by construction** since the CoordinateSharp removal in commit `e602bdb`. Verified: zero *mutable* static fields, zero static caches / dictionaries / `Lazy<T>`, zero ambient-clock reads outside `ObservationMoment.Now`; all static state is **immutable and enumerable** — the four Meeus/Bortle tables, `VisibilityWindows.ProfileScanStep`, and the five canonical singletons the 2026-05-27 sweep introduced (`Location.Default`, `Target.Default`, `MoonLimitProfile.Disabled`/`Narrowband`/`Broadband`). All public APIs take parameters with no hidden state.

**This is a re-runnable audit, not a one-time observation** — re-establish it after any refactor that adds static state (run three times so far: the 2026-05-18 review, its post-refactor recheck — `archive/2026-05-18-library-review-recheck.md` — and the 2026-08-11 maintain sweep, which passed it exactly as written). The recipe: grep `Astronomy.Core` for sync primitives (`lock` / `Interlocked` / `Monitor` / `SemaphoreSlim` / `Mutex` / `SpinLock`), for `[ThreadStatic]` / `ThreadLocal<T>` / `Lazy<T>` / `ConcurrentDictionary`, and for ambient-clock reads — then confirm every remaining `static` field is immutable and individually accounted for. The verdict rests on **naming** the permitted static state, never on asserting there is none; that enumeration is what keeps the claim honest as the set grows. All inputs are immutable POCOs (`Target`, `Location`, `NightWindow`, `MoonLimitProfile`); all returns are immutable POCOs, small structs (`AltAz`, `RiseSetResult` — note `RiseSet` itself is the static helper class, not the value type), or `IReadOnlyList<T>`. **Consumers may call any helper from any thread without external synchronization.**

Two caveats limit that promise:

1. **Caller-supplied delegates are the consumer's responsibility.** Methods that take `Func<...>` parameters — most notably `IntegratedQuality.OverSession(..., Func<double, double> altitudeQuality)` and `IntegratedQuality.HalvesAroundMidpoint(...)`, plus any future delegate-taking helper — invoke the delegate from whatever thread called the method. If a consumer passes a closure that mutates captured state (e.g. `int count = 0; alt => { count++; return ...; }`), thread safety of that closure is on the consumer. Pure / referentially transparent functions are always safe. **The same delegates carry a NaN contract, not just a thread-safety one:** they must return **finite** values across `[-90, 90]`, because a `NaN` or infinite return flows straight into the Simpson sum and silently corrupts the integral — there is no runtime guard. A quality function that rejects below-horizon samples must return `0`, never `double.NaN`.

2. **`Astronomy.PCL` is NOT part of this contract.** PCL is a separate assembly (`Astronomy.PCL.csproj` + `Astronomy.PCL.Native.vcxproj`) wrapping the vendored PixInsight Class Library. `Astronomy.Core` never references it. The underlying PCL C++ library historically isn't safe to call across threads — assume single-threaded access until PCL's own concurrency story is documented per-API.

`NightCache` is a per-`Location` amortization helper: build once per caller planning pass, hand to multiple targets so each target's year work doesn't re-derive the same 365-day `NightWindow` series. The instance is immutable after construction; concurrent readers are safe. Several caches can be built in parallel for different locations.

## Code organization (high-level)

All ten folders, so the map matches the tree:

- `AltAz.cs` / `TargetGeometry.cs` — topocentric coordinate primitives (the core "where is this target right now" math).
- `FieldFootprint.cs` — rotated-rectangle **overlap fraction** on a tangent plane (Sutherland-Hodgman clip + shoelace; exact for convex). RA offsets are scaled by `cos(dec)` — without that, east-west offsets inflate ~2.8× at M81's declination. Pure geometry, no catalog knowledge; `Astronomy.Catalog`'s framing pricing is its caller.
- `Astrometry/` — the provenance core: `Meeus/` (the Meeus-backed algorithm implementations everything else rests on), plus `AstroUtil` (the moon/util entry points; consumes `SiderealTime`), `Refraction` (Saemundsson wrapper over `MeeusUtility`), the DTOs `ObserverInfo`, `RiseAndSetEvent`, and `WcsOrientation` — **normative spec: `openspec/specs/wcs-orientation/`** — the plate-solution surface (2026-08-06): `FromCdMatrix(cd11..cd22)` derives position angle (North-toward-East, `[0, 360)`), image-axis rotation, mirror parity (from the CD-matrix determinant sign), and per-axis arcsec/px scale, using NINA's `WorldCoordinateSystem` as strategy reference (pinned by its real-matrix + flip vectors; provenance rule → `DOMAIN.md`). Domain of validity: normal and single-mirrored images only — a both-axes mirror is indistinguishable from a 180° rotation by construction — and solver-specific offsets (e.g. ASTAP's 180°) stay with the calling wrapper. Consumer pinout (XFM's ASTAP solve) → `CONSUMERS.md`.
- `Time/` — `JulianDate` (the central UTC contract gate), `SiderealTime` (GMST/LST), `ObservationMoment`, `TimeKindGuard`, and (2026-08-11) `UtcInterval` (readonly record struct — the half-open UTC interval value type the session/moon/sun interval producers converged on) + `Intervals` (set algebra over ordered interval lists).
- `Locations/`, `Targets/` — the immutable observer + target value types described above.
- `Horizons/` — `IHorizonProfile` and four implementations (`Scalar`, `Polyline`, `ObstructionTable`, `MaxOfHorizonProfile`) for flat-vs-azimuth-varying horizon math.
- `Night/` — twilight calculation, `NightWindow` (a single night's astronomical/nautical/civil dusk/dawn), `NightCache` (year-of-nights for one location).
- `Session/` — higher-level analysis built on the primitives: `AltitudeCurve` (uniform-grid sampling via linear LST advance — the speedup over per-sample `AltAzCalculator.At` comes from GMST being linear in UT, so the curve advances LST arithmetically instead of recomputing it; returns `IReadOnlyList<AltAzSample>` with `AltDegGeometric` + `AltDegApparent` + `AzDeg` per sample), `SessionAltitude`, `QualitySamples`, `AltAzSample`, `RiseSet`, `TransitTime`, `VisibilityWindows`, `CoarseVisibility`, `IntegratedQuality`, `BestSession`, `TargetOrdering`, `SessionSolvers`.
- `Sun/` — `SunPosition`, `SunEvents`, `SunPower`, `SunTracking`, `SunSeparation`, `SunHeliographic`.
- `Brightness/` — `SkyBrightness` (Krisciunas–Schaefer), `Bortle`, `Twilight`.
- `Moon/` — **normative spec: `openspec/specs/moon-brightness-gate/`** (the gate's Δmag acceptance semantics, twilight-in-the-moonless-baseline, apparent-altitude convention, `null` ≡ Disabled short-circuit, boundary interpolation, and fail-fast on a below-horizon target are single-sourced there; the *why* behind the tolerance defaults is in `DOMAIN.md`). `MoonSeparation`, `LunarAge`, `MoonLimitProfile` (the K-S Δmag moon gate's parameter POCO — the gate math lives in `Brightness/SkyBrightness.KsMoonDeltaMag`, the walk in `Session/BestSession.MoonClearIntersect`; the gate refracts moon altitude internally while `ObserveAt` stays geometric); `MoonEphemeris.Sample(location, startUtc, step, count)` returns `IReadOnlyList<MoonSample>` with topocentric AltAz (geometric + apparent) + `DistanceKm` + `AgeDays` + `PhaseAngleDeg` + `IlluminatedFrac` per `step`. Pure-function per-night sampling primitive; who consumes it (and the exact-`count` contract) is in `CONSUMERS.md`.
