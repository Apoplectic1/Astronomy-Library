# Astronomy.Contracts.Tests

*(ARCHITECTURE reference set — split out of the root `ARCHITECTURE.md` 2026-08-11, one file per buildable module; the root file is the index. Charter: subsystem mechanics — how this module is built and works.)*

- **`Astronomy.Contracts.Tests`** — `net10.0-windows` x64, `OutputType=Exe`. xUnit v3 **contract bench** — the pure-managed test project that pins the de-facto Library API contract documented in `CONSUMERS.md` (the consumer "pinout"): the input-contracts and the write safety-gate, over **six of the nine shipped managed assemblies** (Core, XISF, Catalog, Diagnostics, Diagnostics.Windows, NINA — the `.WinForms`/`.WinUI` shells are deliberately outside the bench; boundary rationale → `CONSUMERS.md` § *How this is validated*). Every `CONSUMERS.md` assumption is either covered by a citing test or registered with a reason in `NotCleanlyTestableAssumptions.cs` (the covered-or-registered rule; normative spec in `openspec/specs/contract-assumption-pinning/`). Run by the constellation-level DRC `..\build-all.ps1` (one level up at the `Astronomy\` root) so a Library change that breaks a consumer assumption fails loudly. References only public Library surface — no native dep → builds with `dotnet build`. **Bench scope rule** (decided at `openspec/changes/archive/2026-07-07-contracts-tests-refresh/design.md` § Context/Non-Goals): the bench exists for its *label and its failure message*, not for coverage — deliberate overlap with the unit-test projects is acceptable, but only assumptions traceable to a numbered `CONSUMERS.md` line belong here; implementation details no consumer bakes in stay in the module test projects.
- **The `LogProcessGlobal` rule.** Any bench class that calls the process-global `Log` static surface **must** join `[Collection("LogProcessGlobal")]` alongside `LogLifecycleContractTests`, which serializes exactly those classes while the rest of the bench stays parallel. With process-global static state, *"doesn't `Init`" is not the same as "doesn't touch"*: a class relying on pre-`Init` calls being silent no-ops has them turn into live `File.AppendAllText` writes the moment the lifecycle test's phase-2 `Init` lands in a parallel class, and that writer holds `FileShare.Read` only — so it races the lifecycle test's own `File.ReadAllText` (intermittent ~1-in-3 `IOException`; diagnosed 2026-07-24, `NOTEBOOK.md`).
