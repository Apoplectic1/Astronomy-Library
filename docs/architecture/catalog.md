# Astronomy.Catalog

*(ARCHITECTURE reference set — split out of the root `ARCHITECTURE.md` 2026-08-11, one file per buildable module; the root file is the index. Charter: subsystem mechanics — how this module is built and works.)*

- **`Astronomy.Catalog`** — `net10.0-windows` (`AnyCPU;x64`), `LangVersion latest`, `Nullable enable`, `ImplicitUsings enable`. The shared catalog-database library **and** the owner of the .xisf-library scanner. One `Catalog.db` (SQLite via `Microsoft.Data.Sqlite`, plus a **deliberate direct `PackageReference` the code never calls** — `SQLitePCLRaw.bundle_e_sqlite3` 3.0.5, pinned to override the vulnerable native engine 2.1.11 that `Microsoft.Data.Sqlite` 10.0.10 pulls transitively, CVE-2025-6965; there is no 2.1.12, the package renumbered to a 3.x line. It flows to every Catalog consumer and **must not be "cleaned up" as unused**) reconciles two sources onto **one canonical `target`**: the disk image library is **ACTUAL** (source of truth), N.I.N.A. Target Scheduler is the **PLAN**, and the catalog re-organizes the plan clean and anchored to actual. Each `target` carries both facets (disk identity + plan attributes) discriminated by `source_id` — `Actual` (on disk only), `Planned` (in TS only / not yet shot), `Both` (merged); `inventory_filter` (actuals per filter) and `exposure_plan` (goals) both hang off it. Pure-managed → builds with `dotnet build`. **ProjectReferences: `Astronomy.XISF` (the scanner's header reads) and, since 2026-07-29, `Astronomy.Core`** — the framing overlap rule calls `Core.FieldFootprint`, so the sky-geometry sits in the dependency-free base beside the night-window math rather than being duplicated inside a reconciliation namespace. Core is the base of the graph, so the edge is acyclic. Consumers → `CONSUMERS.md`. By folder:
  - **`Scan/`** — the moved `ImageLibraryScanner` + report types (depends on `Astronomy.XISF`), `MosaicConvention`, `FilterPurpose` + `FilterPurposeClassifier`, and the **framing** types (2026-07-29): `FramingCluster` (a unit's (field-center, sky-rotation) group, fold-180 with per-cluster centroid; tolerance constants live here) + internal `FramingClusterer` (expression partition sky/mechanical/unknown → fold-180 gap clustering → field-center single-linkage split, so a pier flip merges and a translated stray separates). The framing cluster is part of the aggregate identity alongside filter/purpose/exposure/gain/offset/binning/camera; mechanical rotation is never converted to sky (remount zero-point drift). A cluster also carries its **footprint** + a spans-sensors flag (dominant sensor when frames span two, never a blend). **Identity comes from the directory tree, not the frame headers**: target/camera/filter directories are authoritative (the camera directory is known before a file is opened), while header-borne facts — OBJECT name and RA/Dec — are **consensus-reduced across a unit's frames** (median coordinates, name consensus), and a frame recording nothing is treated as *silent, not in disagreement* — only a frame that positively contradicts its directory counts as a mismatch (`CHANGELOG.md` § 2026-05-18 Phase A). **Two whole classes of target never enter the scan** — non-sidereal ones (`IsNonSiderealDirectory`; the `"Comet "` prefix is evidence for non-siderealness, not the fact itself, and its **trailing space is load-bearing** — `"Cometary Globule CG4"` and `"NGC 2261 - Comet Nebula"` are sidereal and still scanned) and the `Calibration/` tree. Both are excluded at the directory walk inside `ScanTargetAsync`, one guard serving both entry points, rather than filtered downstream by each consumer. **Scan resilience:** `ScanAsync` runs per-target scans in parallel (`Parallel.ForEachAsync`) and a per-file header-parse failure is **non-fatal** — recorded in `ImageLibraryReport.SkippedFiles`, not aborted on. That is the one deliberate exception to the portfolio's fail-fast-on-contract-violation default (a single unreadable frame must not lose a whole library scan); the surgical `ScanUnitsAsync` path deliberately surfaces no `SkippedFiles`. The tolerance is **per-file only** (2026-08-11): a unit none of whose readable frames carries RA or DEC aborts the scan with `InvalidDataException` naming the directory — coordinates are required for aggregation, and the former silent (0,0) fallback was a real sky position; the scanner never invents one.
  - **`Build/`** — the reconciliation. Anchoring is **scope-equal only**: every resolvable unit carries a coordinate *scope key* — top-level units (and TS targets outside `isMosaic` projects) share the default scope, a panel sits in its mosaic's scope, and a mosaic **parent is in no coordinate scope at all** (name matching *is* its mechanism). A cross-scope match — a panel's goals landing on a sky-overlapping standalone directory — is therefore impossible **by construction**, not filtered out after the fact; that is why the resolver stays one loop instead of growing mosaic branches. `TargetResolver` (pure, **coordinate-primary** — each TS target anchors to the nearest disk target within a tolerance, default 0.5° haversine; an *unaligned* mosaic-panel claim is limited to the tighter `PanelMatchToleranceDegrees`, default 0.1° — a name-aligned panel directory anchors at the full tolerance since the name confirms identity, while a merely-nearby unrelated framing stays unclaimed; name only validates; **name alignment also gates a second, separate mechanism — a post-anchor *outranking* pass**: when one disk unit accumulates several TS claims and at least one is name-aligned, every unaligned claim is *released* back to unanchored (it applies to any unit, not just panels, and runs before name-validation reporting so released claims don't also flag). The rule **only ever demotes, never invents** — with no aligned claim at all, the nearest unaligned match stands and is flagged. This is what keeps an unshot panel inside tolerance of a shot neighbour classified `Planned` instead of false-folding onto it, and it decides whether a TS row lands in `UnanchoredTsTarget` vs `AmbiguousMatch`; disk plate-solved coords win on merge; the TS guid is **retained on `Both` for write-back**; TS duplicates fold onto one canonical and name-mismatch / ambiguous / unanchored / out-of-range rows are reported in `CatalogBuildReport` — typed rows `NameMismatch` / `AmbiguousMatch` / `UnanchoredTsTarget` / `InvalidTsTarget` / `DuplicateTsTarget` — not dropped). **Harden rule:** never pass a raw TS integer into a CHECK/FK column — `TargetResolver` coerces unknown epoch/state/priority codes to a safe default and normalizes/clamps planned RA/Dec, so a single bad external TS row can't abort the rebuild. **Epoch is the one field needing a translation table, not a bounds check** (2026-08-01): TS persists NINA's `Epoch` enum ints (**JNOW=0, B1950=1, J2000=2, J2050=3**) — the *reverse* of the Catalog's own epoch lookup for codes 0/1 — so `SafeEpoch` maps known codes through an explicit switch; a bare cast had silently swapped JNow↔B1950 for any non-J2000 TS target (latent — every real target is J2000). Unmodeled codes (incl. J2050) coerce to J2000 and are still reported via `FlagIfSuspect` per the coerce-don't-abort rule; a `[Theory]` pins codes 0–3 (derivation: `NOTEBOOK.md` § 2026-08-01). `CatalogBuilder.BuildAsync` is the full rebuild: scan disk + read TS → resolve → `WriteCatalog` in one transaction; either source may be omitted.
  - **`Schema/`** — the POCOs/mappers + `schema.sql`. (`SchemaManager`, `CatalogStore`, `GuidBlob` and the `Data/` mapper plumbing — `ITableMapper`, `SqliteReaderExtensions` — live at project root / `Data/`.) `SchemaManager` applies `schema.sql` idempotently — **no migration framework**: the catalog is fully derived (scan + TS import) and rebuildable, so a schema change just means deleting `Catalog.db`. `CatalogStore` is the read/write surface: `WriteCatalog(graph)` replaces the whole catalog transactionally; `GetShotTargets()` = source `Actual`|`Both` **and `parent_target_id IS NULL`** is the actual-only view — a `Both` target has frames on disk, so it belongs; planned-only is excluded, and so is every mosaic *panel* child even when it has frames, since the query returns only the parent grouping node — descend with `GetChildTargets(parentId)`. **A mosaic is modelled as a parent target plus one child target per panel** (`target.parent_target_id`, indexed `ix_target_parent`); that hierarchy is what per-panel write-back and panel-radius gating operate on.
  - **`TargetScheduler/`** — `TargetSchedulerReader` reads TS's `schedulerdb.sqlite` read-only (Mode=ReadOnly + busy-timeout, explicit columns). `TargetSchedulerWriter` (+ pure `WriteBackPlanner` / `SingleTargetPlanner`) writes reconciled disk counts back into a **local** TS copy (Phase 4 engine — bulk or surgical single-target, per panel for mosaics; column-presence-validated, read-back verified; returns `WriteBackResult` with `WriteBackChange` / `WriteBackVerifyFailure` rows). On the write-back side a multi-claimed cell is *withheld* rather than merely reported: `WriteBackPlanner` holds it out of the auto-write plan as a `ManualGroup` carrying a structured `ManualReason` (`MultiPlan` / `DuplicateFold` / `IdentityConflict` / `NoMatchingPlan`) plus the competing `ManualPlan` rows for hand resolution, with `ReconcileNote` / `UnplannedFrames` for the no-plan case; consumers render that hold-back surface. (The alias-fold escape that used to auto-write ex-alias multi-claims was removed 2026-07-23.) **Write-back groups every existing plan, not just those on `Both`-resolved targets** (2026-07-23, "disk truth covers absence"): a plan whose target has no disk match stamps 0 like any other unmet spec, so stale counts and diverged accepted/acquired pairs on not-yet-shot targets *heal* instead of persisting forever — while `IgnoredMissing` counts only disk-only targets, and write-back still never creates or deletes plan rows. Write-back groups plans on the four-part key **(target, filter, purpose, whole-second exposure)** and, within the bucket, **credits only frames whose capture configuration pairs with the plan's template** (2026-08-04, `pairing-credited-write-back`): `CaptureConfigPairing` is the single gain/offset/binning predicate (value equality after plan-side normalization; the camera-default sentinel `-1` pairs with nothing), shared by `ReconciliationProjection`'s cell key, `WriteBackPlanner`'s credit sum, and `SingleTargetPlanner`'s cell routing — never folded across durations or configurations. **The sentinel normalization is deliberately asymmetric**: an unspecified gain or offset becomes the `-1` camera-default sentinel — which equals no captured value, so it credits **zero frames forever**, surfaced as `ReconciliationCell.TemplateSentinel` (gain/offset only, by design — the consumer's cue that the plan's configuration must be made explicit at its source) — whereas **binning has no sentinel convention at all**: an unspecified or non-positive plan binning reads as `1` and therefore *does* pair with bin-1 disk frames. Sentinels that are a field's designed deferral state (a template's readout mode, a plan's defer-to-template exposure) are correct by construction and never raise the flag (contract statement + the zero-is-a-real-write corollary: `CONSUMERS.md` assumptions #26–#29, promoted 2026-08-11 — write-back is #27). **Write-back likewise credits only frames whose framing serves the plan** (2026-07-29): `FramingCluster.ServesPlanRotation` is the single rotation-participation predicate, shared by the same three call sites — so the consumer's badge and the stamped counts can never tell different stories. A non-serving disk framing is **excluded from the count entirely** (bulk *and* surgical), not merely flagged: a re-framed plan stamps its true progress, possibly 0, and a withheld surgical cell emits a `FramingMismatch` note naming the frames, the framing, and the rotation they fail. Mechanical/unknown framings and rotation-less targets always credit; fold-180 flips still credit. **Dry-run is supported but not a default** — `Execute(WriteBackPlan plan, bool apply)` takes `apply` as a required argument, so every caller states intent explicitly; the "default" belonged to the `--apply`-off CLI verbs, which retired with the consumer's console host 2026-06-11, to resurface as a TSM app action.
  - **`Reconcile/`** — goal-vs-actual. `Reconciler` + `CatalogStore.GetReconciliation`: TS goals (`exposure_plan.desired_count`) vs disk actuals (`inventory_filter`) per (target, filter), joined on the shared single-letter filter name — actuals are disk truth (TS's stale `acquired_count` is ignored). `ReconcilePolicy.Combined` (default) counts Light + Stars toward a goal; status is NotStarted/InProgress/Complete/Unplanned. `ReconciliationProjection.Project(graph, report)` flattens the graph into per-target `TargetCells` / `ReconciliationCell` rows — the grid-shaped projection consumers bind directly. Its cell key is the capture configuration **plus the framing cluster** (2026-07-29): a plan pairs with the disk framing whose sky rotation agrees fold-180 with the target's rotation; mechanical/unknown framings and rotation-less targets skip the rotation term (it never prevents pairing), and a disk cell whose sky rotation fails the plan carries `FramingDisagrees` for the consumer's badge. **The general rule behind both exclusions: a plan and a disk aggregate pair only on dimensions *both planes can express*** (2026-07-27). Camera is disk-side only — a TS profile cannot name a camera, so keying on it would split cells against a plan that could never match — so it rides the aggregate as a label plus a `CameraDisagrees` flag that never prevents pairing; the same rule is why mechanical/unknown framings and rotation-less targets skip the rotation term. Disk-side aggregate identity (filter/purpose/exposure/gain/offset/binning/camera/framing) is therefore deliberately *wider* than the pairing key. An off-footprint framing is also **priced, not just flagged**: the overlap fraction is the share of the framing's own footprint landing inside the plan's rectangle, measured against **that framing's own dominant sensor** (never a neighbouring framing's), via `Astronomy.Core.FieldFootprint`. A serving framing prices nothing while it stays at or above `FramingCluster.OnFootprintFraction` (0.95); a disagreeing one always reports whatever its overlap, so a badge is never left pointing at an empty cell. The fraction means off-footprint for *any* reason — wrong rotation, wrong pointing, or both — and crediting stays the boolean `ServesPlanRotation`: a partially overlapping frame is not a fractional frame.
  - **`Intent/`** (2026-08-12, openspec `add-intent-store`) — the **authored intent store**: a *second, separate* store class in the same project, deliberately distinct from the derived catalog above. Where the derived `Catalog.db` is rebuildable disk⊕TS reconciliation, the intent store is **permanent, user-owned authored truth** (profiles, projects, targets, exposure templates/plans with *desired counts only*, blessed interval plans) — and therefore **migrated, never rebuilt** (the portfolio's rule-15 exemption made concrete; schema authority: ISM `docs\design\catalog-db-schema.md`). It deliberately has **no actuals surface** — no acquisition-history tables, no acquired/accepted columns — because progress truth is the disk library, scanned fresh (plan-db + fresh-scan shape). Pieces: `Intent/Migrations/0001_initial.sql` (baseline DDL as migration 1 — enum lookups **with companion CHECKs**, every FK indexed `ix_<table>_<col>` incl. enum FKs, GUID BLOB PKs via `GuidBlob`, plan plane minimal: `plan`/`plan_interval` referencing `exposure_plan`); `IntentMigrations` (the portfolio's first migration framework: embedded `NNNN_name.sql` scripts, per-script transactions each logging a `schema_migration` row + syncing `PRAGMA user_version`, newer-than-library aborts, failure rolls back to the prior version; the log table itself is the one framework-owned bootstrap); `IntentStore` (open = local-path guard → migrate → configure; **UNC/network paths refused before any file exists** — the store is local-only and single-writer by system invariant; `Dispose` = WAL `checkpoint(TRUNCATE)` + close, and **`Pooling=false` is load-bearing** — a pooled handle would outlive Dispose and break the closed-store-is-one-consistent-file sync-safety contract; store path is always the caller's configuration, no default constant in AL); `TsImport/` (the one-time TS lift: own read layer with the full in-scope field set — the shipped `TargetSchedulerReader` records stay untouched — `TsImportMaps` R13 translation maps incl. the pinned NINA→AL epoch swap with abort-on-unmapped, sentinel→NULL boundary translations, empty-store precondition, single all-or-nothing transaction, `imported_from_ts_guid` provenance on every lifted row, mosaic parent **synthesized** per mosaic project — the parent is reconstruction, not a lifted row: NULL coords, NULL provenance, lineage via `project_id`). The operational lift runs from the env-var-gated `TsImportDriver` in `Astronomy.Catalog.Tests` (`INTENT_IMPORT_TS_DB` / `INTENT_IMPORT_STORE`): lift → verify (counts vs source, provenance resolution, drift spot-checks). **Write/lookup surface** (2026-08-12, openspec `add-intent-write-surface`): `IntentWriter` over an open store — full-value `ON CONFLICT(id)` upserts for the four intent-plane entities via schema-mirror records (`ProjectIntent`/`TargetIntent`/`ExposureTemplateIntent`/`ExposurePlanIntent`; `created_at` caller-supplied on create and **excluded from the update set**, NULL means unset per R3, DDL defaults mirrored as record defaults) + per-entity provenance lookups (`Find<Entity>Id(importedFromTsGuid)` — none → null, duplicate → loud), every operation taking an optional caller-owned `SqliteTransaction` (the writer never begins/commits its own). Migration `0002_minimum_time_nullable.sql` (R10 table-rebuild relaxing `project.minimum_time_minutes` to nullable; the live table is never renamed — only the throwaway rebuild name, so child `REFERENCES` clauses stay untouched) and the framework posture that enables rebuilds: `IntentMigrations.Apply` suspends `PRAGMA foreign_keys` around the apply loop (the pragma is a no-op inside a transaction, so scripts can't own it) and gates every script's commit on a whole-store `PRAGMA foreign_key_check` (violation → rollback + loud failure). First consumer will be ISM; nothing links it today.

The largest suite in the repo.
- `TargetSchedulerEditor.TrySetField(table, key, column, value) → (FieldEditResult?, RefusalReason)` is the **sole public field-edit path** (since 2026-07-24; the formerly-public ungated `Set*` setters were removed — `SetField` survives internal as its engine, and a contract test pins the surface shape): it folds the four open-db predicates (required columns / read-only / open sidecar / column present) into one structured-refusal call, plus a cadence guard — editing a target that has hand-authored override-order rows is refused (`RefusalReason.HasOverrideOrder`) rather than silently invalidating them. Consumers map `RefusalReason` to their own wording — the library names none.
- `TargetSchedulerEditor.TryInsertRows(rows) → (InsertOutcome?, RefusalReason)` (2026-08-03) is its **row-creation sibling** — the only public insert path: one batch-atomic transaction over `TsRowInsert(Table, Payload)` records (exposuretemplate / target / exposureplan; all rows or none), same guard order as `TrySetField`, per-table required payload columns, payload column names validated against the live schema (the whitelist role `PRAGMA table_info` plays for edits), parent references (`projectid` / `targetid` / `exposureTemplateId`) accepted as integer id **or guid** and resolved in-transaction (a guid may name a row inserted earlier in the same batch), a plan insert clearing the target's `filtercadenceitem` rows in-transaction with the `HasOverrideOrder` refusal, and read-back verification per row (`RowInsertResult`). Journaling/replay semantics stay consumer-side — the library mints nothing but the rows.
- `TargetScheduler/TsEditableSchema` is the **declarative editable-field surface**: per-field `TsField` records (`Label`/`Type`/`Min`+`Max` bounds/`Sentinel`+`SentinelLabel`/`Guarded` arm-before-edit/`Clears`/`EnumName`/`Notes`) over the target/project/exposuretemplate tables, `TsFieldType` + `TsEnumValue` (`EnumValues`) so consumers render editors with zero UI-side schema, and `TsCadenceClear` (Target/Project/None) declaring which edits are cadence-breaking. It carries two further load-bearing roles beyond rendering: it **is the SQL-injection whitelist** (the column name is interpolated into the `UPDATE` while key and value are parameterised — only a declared field can reach the SQL), and it is the **open-time schema-drift guard** (the editor reflects each table via `PRAGMA table_info` at open and refuses `ColumnAbsent` for a field this TS version lacks). **The sentinel convention is first-class field metadata**: TS expresses "unspecified — defer to the enclosing scope" as a negative sentinel on numeric columns, and `TsField.Sentinel` + `SentinelLabel` name *where* each defers (`exposureplan.exposure` −1 → "template default"; template gain/offset/readoutmode −1 → "camera default"; `ditherevery` −1 → "project default") so a schema-driven consumer renders and round-trips the deferral instead of displaying a raw −1 it can never write back. Two field-level rules worth knowing (2026-08-06, v1.4.0): **`minimumaltitude` Max clamps to 89.9, not 90** — TS's `HorizonDefinition` asserts `< 90` at plan time, so a 90 write would pass the editor and abort TS planning — and **`project.name` is itself editable** (Text field) so a landed altitude write can also rewrite an existing name's altitude clause (`MosaicConvention.StripAltitudeClause` tolerates both the legacy `" - Above N"` and short `" - N"` clause forms with an end-anchored dash). Every write is **read-back verified** — `TrySetField` clears the affected `FilterCadenceItem` rows transactionally with the write. `TargetSchedulerEditor.ReadPlanEffectiveExposure` resolves a plan's exposure through its template via the standalone `EffectiveExposure` rule class (shared by catalog-side and raw-TS-side resolution).
