# Astronomy.PCL / Astronomy.PCL.Native

*(ARCHITECTURE reference set — split out of the root `ARCHITECTURE.md` 2026-08-11, one file per buildable module; the root file is the index. Charter: subsystem mechanics — how this module is built and works.)*

- **`Astronomy.PCL.Native`** — vcxproj, x64-only C++ DLL. Statically links the vendored PixInsight Class Library (`Library\PCL\lib\x64\$(Configuration)\*-pxi.lib`). Public surface is the `extern "C"` C ABI in `include\Astronomy\PCL\XisfCApi.h`. Mirrors PCL's build flavor (`/MD`, `/fp:fast`, `stdcpp17`, `__PCL_WINDOWS`, `__PCL_AVX2`, `__PCL_FMA`) using the same MSVC toolset PCL itself uses (`v145` as of VS2026 — both wrapper and PCL bumped together); compiled with `AdvancedVectorExtensions2` (AVX2) — and since 2026-07-24 the **entire linked closure is too**: `PCL.vcxproj`, the six 3rd-party libs and `xisf.vcxproj` were restored to `AdvancedVectorExtensions2`, which is **upstream PCL's own configuration** (the zip's pristine vc16 projects: AVX2 + `__PCL_AVX2`). The local vc16→vc17/vc18 port had silently escalated the compiler flag to `AdvancedVectorExtensions512` while the `__PCL_AVX2` source macros stayed put, letting MSVC auto-emit ungated AVX-512 into the static libs (measured: 5,635 AVX-512 instructions in the Release wrapper DLL; zero after the restoration, verified by `dumpbin`). The floor matters because the portfolio's minimum target is the imaging machine's Ryzen 7 4800U — **Zen 2: AVX2 + FMA, no AVX-512** — where the escalated binaries would have died with an illegal-instruction fault the first time IS touched the wrapper. Don't raise the flag again without raising the portfolio's hardware floor. The wrapper itself does no numerical work, but matching PCL's flags keeps any PCL header inlines instantiated in the wrapper TU bit-identical to the same inlines inside the static libs.
- **`Astronomy.PCL`** — `net10.0-windows` x64, `LangVersion latest`. Managed P/Invoke wrapper. Public surface: `XisfFile : IDisposable` (`Open` / `FilePath` / `ImageCount` / `SelectImage(index)` **returning `XisfImageInfo`** / `ReadImageF32()` returning a fresh array, plus the caller-allocated `ReadImageF32(float[] destination)` overload — prefer the latter in a loop), `XisfImageInfo`, `XisfColorSpace`, `XisfException`. Internal `NativeMethods` in `Interop/` holds the `[DllImport]` declarations. `<InternalsVisibleTo Include="Astronomy.Core.Tests" />` lets the smoke test bypass the wrapper. (TFM history — net8.0 → net10.0 → `net10.0-windows` — is shipped history: `CHANGELOG.md` 2026-05-04 / 2026-05-11.)

`Library\PCL\` is the vendored PixInsight Class Library — **~19 GB** extracted (`src\` 16 GB, `bin\x64` 2.9 GB of module outputs, `lib\x64` 351 MB of the static libs this repo actually links, `include\` 8.3 MB). It's gitignored — re-extract from `PCL\PCL-master.zip` (snapshot pinned 2025-02-22 per `archive/PCL-InterOp.md`) on a fresh clone.

## PCL local build

`Library\PCL\` is the vendored Pleiades PixInsight Class Library, locally pruned to **Windows-only** — the macOS and Linux build trees were largely stripped (some Makefile stubs survive under `Library\PCL\src\modules\...`, but the actual source trees were removed). The canonical pinned snapshot is `Library\PCL\PCL-master.zip` (2025-02-22 per `archive/PCL-InterOp.md`). Re-extract on a fresh clone, or to discard local edits.

> **The build procedure** — re-extract, the four required env vars, building `PCL.sln`, and the
> test-data side effect — lives in `VERIFICATION.md` § *PCL native prerequisites*. What follows is the
> structure it operates on.

**Toolset.** Every **sln-participating** vcxproj (the 46 in `PCL.sln`) is at `<PlatformToolset>v145</PlatformToolset>` — `PCL.vcxproj`, the six 3rd-party libs, `xisf.vcxproj`, *and* all 38 file-format/process modules — matching `Astronomy.PCL.Native`. (The tree holds 53 vcxproj total; the 7 outside the sln — RAW / RAW-compat / INDIClient / EphemerisGeneration, vc16+vc17 variants — were never ported and sit at v142/v143. They aren't built here.) **Instruction set:** the 8 sln-visible projects (PCL + six 3rd-party + xisf) are at `AdvancedVectorExtensions2`, restored 2026-07-24 to upstream's own configuration after the local port had escalated them to AVX-512 (see § *Astronomy.PCL / Astronomy.PCL.Native* for why — the 4800U imaging machine has no AVX-512). The 38 module projects were left at the escalated flag (one stray exception: `Sandbox.vcxproj`'s Debug config sits at `AdvancedVectorExtensions101`): their `.pxm`/`.dll` outputs are unused by this repo and run only inside PixInsight on this machine. The directory naming `vc17` under `src\3rdparty\*\windows\vc17\` and `src\modules\*\windows\vc17\` is historical PCL convention and was deliberately not renamed; only the main PCL solution moved from `src\pcl\windows\vc17\` → `src\pcl\windows\vc18\` to signal the VS2026 build flavor.

**Main solution.** `Library\PCL\src\pcl\windows\vc18\PCL.sln` carries **46 buildable vcxproj**: PCL, the six 3rd-party static libs and the xisf utility (the parts this repo consumes), plus six file-format modules and ~32 process modules that are built but unused here. Static libs land in `Library\PCL\lib\x64\{Debug,Release}\*-pxi.lib`, module and utility outputs in `Library\PCL\bin\x64\{Debug,Release}\` (~2.9 GB). `Astronomy.PCL.Native` consumes only the seven `.lib` outputs from `lib\x64\$(Configuration)\`.

**x64-only, tree-wide.** Every vendored PCL vcxproj declares only `Debug|x64` / `Release|x64` — this is not an xisf-specific local edit. Consequence: the `Debug|x86` / `Release|x86` → `Win32` mappings that `Astronomy.sln` carries for the eight PCL projects point at configurations that **exist in no project file**. They are dead entries (and unlike the x64 rows they carry a live `Build.0`), so selecting the x86 solution configuration fails rather than aliasing to something workable.

**xisf utility.** PCL's CLI test app at `Library\PCL\src\utils\xisf\`. Statically links the same seven `.libs` Astronomy.PCL.Native does (`PCL-pxi`, `lz4-pxi`, `zlib-pxi`, `zstd-pxi`, `lcms-pxi`, `cminpack-pxi`, `RFC6234-pxi`, plus `Userenv`). Built by PCL.sln (which lists xisf.vcxproj) or independently via `xisf.sln` in the same directory; both produce the same `xisf.exe`. (How to invoke it → `VERIFICATION.md`.)

**Re-snapshot caveat.** The snapshot is pinned (2025-02-22) **deliberately, not incidentally** — re-snapshot only for a specific reason to upgrade, because PCL's templated headers can introduce ABI churn that breaks `Astronomy.PCL.Native` if the bump isn't coordinated with the wrapper (`archive/PCL-InterOp.md` § *License note*). Beyond that, re-extracting `PCL-master.zip` clobbers all local edits — the `vc18` directory, the v143→v145 toolset bumps, the Win32/x86 strip, anything else added under `Library\PCL\`. Note the toolset bump spans **~46 project files, not the eight** the tree's own solution highlights: re-applying to only PCL + 3rd-party + xisf leaves the modules on v143 and the solution broken. Plan to re-apply wholesale or keep a patch. **One local edit needs no re-apply:** the AVX2 instruction set — upstream's projects already carry `AdvancedVectorExtensions2`, so a fresh extract is born correct; just don't re-escalate it during the next toolset pass (that's how the AVX-512 drift happened the first time).

**Upstream Pleiades docs.** `Library\PCL\README.md` (PCL overview), `CODING_STYLE.md` (Pleiades C++ conventions), `COPYING.md` + `LICENSE.txt` (PCLL license) are unmodified upstream content; left alone deliberately so re-snapshot doesn't churn them.

## PCL interop

The hybrid architecture from `archive/PCL-InterOp.md` (the archived interop-rationale decision record) is **implemented** for the first surface (XISF read). Two projects:

- `Astronomy.PCL.Native` (C++ DLL, statically links PCL `.lib`s from `Library\PCL\lib\x64\`).
- `Astronomy.PCL` (managed P/Invoke wrapper, `net10.0-windows` x64).

C ABI is the source of truth: `Astronomy.PCL.Native\include\Astronomy\PCL\XisfCApi.h`. Every **fallible** export is wrapped in `ASTRONOMY_PCL_TRY` / `ASTRONOMY_PCL_CATCH` (in `src\Exception.h`) — this catches `pcl::Exception` and `std::exception` and translates to status codes; the `catch (...)` branch picks up SEH (access violations etc.) due to `<ExceptionHandling>Async</ExceptionHandling>`. Two exports are deliberately bare: `AstronomyXisf_Ping`, and `AstronomyXisf_GetLastErrorMessage` — the latter **must never** use the macro, because the CATCH body calls `SetLastError` and would clobber the very thread-local it exists to read. Last-error message is thread-local (`src\LastError.cpp`); consumers retrieve via `AstronomyXisf_GetLastErrorMessage` (two-call idiom: query length, alloc, fetch) — and **must query on the same thread that made the failing call**: fetched from any other thread the message reads empty rather than reporting the error. That is intended per-call-status semantics, not a bug (adjudicated at `archive/2026-05-18-library-review.md` § E3).

Two more host-process survival mechanisms keep PCL from touching the nonexistent PixInsight platform: `SilentLogHandler` (`src\SilentLogHandler.h`, a no-op `pcl::XISFLogHandler` installed on every reader so PCL logging never reaches a nonexistent console) and a file-static `PclRuntimeInit` ctor (`XisfCApi.cpp`) that runs at DLL load and calls `pcl::Exception::DisableGUIOutput()` / `DisableConsoleOutput()` — without it an exception's *destructor* tries to write to the PixInsight GUI console and surfaces as an unrecognized exception type at the catch sites.

**Watch-out: don't use `XISFReader::ReadImage(FImage&)` for non-float source images.** PCL's auto-converting read path appears to need PixInsight platform services that aren't available in a host process — UInt16 or UInt32 sources surface as an unrecognized SEH exception ("Unknown C++ exception" at `catch (...)`). The wrapper dispatches on `ImageOptions.bitsPerSample` / `ieeefpSampleFormat`, reads in the file's native type (`UInt16Image`, `FImage`, `DImage`, …), then converts to float32 in our own loop. See `XisfCApi.cpp:AstronomyXisf_ReadImageF32`.

Adding new PCL surfaces: bind on demand — **and preserve the standing convention that pixel I/O is explicit.** `Open` / `SelectImage` / `GetImageInfo` never read pixel data (metadata costs milliseconds; one `ReadImage` on a 5496×3672 frame costs hundreds of ms and ~80 MB), so a caller pays for pixels only where it asks for them. Any new surface must keep that split rather than quietly decoding on a metadata call. Add the `extern "C"` export to `XisfCApi.h` and `Astronomy.PCL.Native.def`, implement in `XisfCApi.cpp` wrapped in the macro (unless it's an error/diagnostic-retrieval export — see the `GetLastErrorMessage` exception above), mirror the `[DllImport]` in `Astronomy.PCL/Interop/NativeMethods.cs`, expose the C# surface in `Astronomy.PCL`. Test in `Astronomy.Core.Tests/Tests/PCL/`. Three standing rules bound what may be added:

- **Buffer granularity.** A managed→native crossing costs ~20-50 ns — free at file granularity, ruinous per element — so every export is buffer-shaped by rule (buffer in, buffer out, loop natively); no export may be added that a caller would invoke per pixel or per row-element (`archive/PCL-InterOp.md` § Performance).
- **The C ABI never transfers ownership of native memory.** The "native allocates, caller Frees" pattern was deliberately not adopted — there is no `Free` export and none may be added. Every variable-length output is written into a caller-supplied buffer under the two-call size-then-fetch idiom (returning `AstronomyXisfStatus_BufferTooSmall` on under-allocation); the only native-owned resource is the opaque `AstronomyXisfHandle` released by `Close`; every export reports through the `int32_t` status code, never an exception or out-of-band error object (rejected alternative: `archive/PCL-InterOp.md` § Caveats).
- **PCL offers no in-place XISF edit primitive.** `pcl::XISFWriter`'s lifecycle is `Create(path, count)` → write → `Close()`, so any native-path write or metadata edit is necessarily read-source → mutate-in-memory → write-a-fresh-file → atomic replace, never a mutation of the existing file (`archive/PCL-WrapperRoadmap.md` § Hard constraints, constraint 1).
