# ARCHITECTURE.md

**Charter.** Subsystem mechanics — *how each module of the `Astronomy` library is built and works*. Organized **one section per buildable module** (plus the cross-cutting `Astronomy.Core` API conventions and the PCL native/interop/local-build story). Forward-looking design lives in `ROADMAP.md`; how to build/test/benchmark lives in `VERIFICATION.md`; the consumer-facing contract lives in `CONSUMERS.md`; domain rationale (science/unit conventions' *why*, algorithm provenance) routes through `DOMAIN.md`.

## Solution overview

`Astronomy.sln`: **x64 is the only fully-wired build config** (Debug/Release × x64). The solution also exposes AnyCPU/x86 entries, but they're unmaintained aliases — of the seventeen buildable `Astronomy.*` projects, twelve map them to `Any CPU` and five map them to x64 — the four newer x64-only projects (Core.Benchmarks, Contracts.Tests, Catalog.Tests, Diagnostics.Tests — **not** Diagnostics itself, which maps to `Any CPU`) plus `Astronomy.PCL.Native` (vcxproj). The eight vendored PCL projects map their x86 entries to `Win32`, which is dead weight: every vendored PCL vcxproj declares **only** `Debug|x64` / `Release|x64`, so those `Win32` mappings point at configurations that exist in no project file. Always build x64. It holds seventeen buildable projects, plus a `PCL` Solution Folder containing eight view-only PCL projects (`PCL.vcxproj`, the six 3rd-party `.lib`s — `cminpack`, `lcms`, `lz4`, `RFC6234`, `zlib`, `zstd` — and the `xisf.vcxproj` CLI utility) sourced from `Library\PCL\`. The PCL projects have `ActiveCfg` set but `Build.0` omitted **for the x64 solution configs specifically** (other configs carry Build.0, but x64 is the config that's built): full source visibility and IntelliSense / F12 in the IDE, but `Build Solution` and `msbuild Astronomy.sln` skip them. PCL rebuilds happen manually via `Library\PCL\src\pcl\windows\vc18\PCL.sln`.

### Architectural conventions

These are baked into the public API and must be respected when adding code:

- **Hemisphere convention.** `Latitude`, `Longitude`, and `Declination` are stored as **non-negative magnitudes**, with direction in companion bool flags (`Location.North` / `Location.West` / `Target.North`). Constructors normalize by **XOR, not override**: a negative magnitude is flipped positive *and* the companion flag is inverted, so `new Target(declination: -5.0, north: false)` stores `Declination = 5.0, North = true` — i.e. **+5° North**, not −5° South. (Sign "wins" only when the caller passed the positive-hemisphere flag; the two inputs compose rather than one taking precedence.) Internal math reconstructs signed values just before feeding geometry.
- **RA is decimal hours in `[0, 24)`**, not degrees. Declination is decimal degrees.
- **The `AltAz` / `TargetGeometry` altitude is unrefracted** — degrees above the mathematical horizon. This is a convention of the *geometric* primitives, not a library-wide guarantee: `Astrometry.Refraction.SaemundssonDeg` is public, and refracted altitude is a first-class output elsewhere (`Session.AltAzSample.AltDegApparent`, and the apparent-altitude paths in `AltitudeCurve`, `MoonEphemeris`, `SunPosition`, `SkyBrightness`). When adding a refraction term, be explicit about which of the two you are producing and coordinate across `AltAz`, `TargetGeometry`, `RiseSet`.
- **Azimuth** is degrees from North, clockwise, in `[0, 360)` — **half-open**. Due north is the seam: the `cosAz` clamp forces exactly `1.0` for a target north of the zenith, `Acos(1.0)` is exactly `0.0`, and the eastern-half flip computes `360.0 - 0.0`, so `AzimuthAtHourAngle` folds `>= 360.0` back to `0.0`. Nothing downstream renormalizes (`AltAz`'s ctor stores verbatim), so the fold has to happen at the source.
- **DateTime kinds — UTC is a hard contract, enforced centrally.** `Astronomy.Core.Time.JulianDate.FromUtc` is the single gate: every time-based primitive funnels through it (`SiderealTime.Local` routes there; normalizing callers arrive as `FromUtc(AsUtc(x))`), and it **throws `ArgumentException` on a non-`Utc` `Kind`** rather than reinterpreting. The reason is that `DateTime.ToOADate()` ignores `Kind` entirely and reads raw ticks, so a `Local`/`Unspecified` instant would be silently reinterpreted as UTC and return an answer wrong by the caller's UTC offset. Because the gate is central, no downstream primitive needs its own guard.
  - `TimeKindGuard.AsUtc(DateTime)` (internal) remains the **converting** sibling for entry points that accept a local-frame instant (`AstroUtil`, `MoonEphemeris`, `NightCalculator`, `Sun/*`): `Local`/`Unspecified` are treated as local and converted via the machine zone; `Utc` is a no-op. Converting entry points therefore still accept any `Kind`; everything else requires `Utc`.
  - `NightWindow` outputs are `Kind=Utc`. The recommended consumer-facing carrier is `Astronomy.Core.Time.ObservationMoment` (record struct, `(Utc, Zone)`) — build via `FromLocal(local, zone)` or `Now(zone)` and pass `.Utc` to math helpers.
  - `LunarAge.DaysAt` predates the central gate and throws on its own; it is now consistent with the gate rather than an exception to a lenient rule.
- **Immutability + `With(...)`.** `Location` and `Target` are immutable; mutations produce new instances via a `With` method that takes optional parameters.
- **Canonical singletons are `public static readonly` fields**, never expression-bodied `=> new T(...)` properties (swept library-wide 2026-05-27; `Target.Default`, `Location.Default`, the `Filter.H`…`B` presets, `MoonLimitProfile.Disabled`/`Narrowband`/`Broadband`). The owning types are immutable, so one shared instance is safe and there is zero per-access allocation on cold paths — but the load-bearing part is that **callers may rely on reference identity**: a consumer caching on these keys can compare with `ReferenceEquals` (TP's `ChartCacheStore` keys four cache axes that way). Re-introducing a factory property would silently break those callers rather than fail to compile.
- **D/M/S accessors are computed on read**, never stored. Don't add stored DMS fields — they would drift.
- **Missing XML docs on public members are a build error, not a warning**, in four of the nine shipped managed assemblies: `Astronomy.Core`, `.NINA`, `.PCL`, `.XISF` each set `<WarningsAsErrors>$(WarningsAsErrors);CS1591</WarningsAsErrors>`. The rest opt out deliberately, with the rationale in each csproj: `Astronomy.Catalog` (`NoWarn;CS1591` — the schema POCOs sit 1:1 with the documented SQL, so per-column docs would be noise) and the four Diagnostics-stack assemblies (`NoWarn;CS1591`, core/`.Windows`/`.WinUI` also `CA1031` — the severity members are self-describing; best-effort swallow-alls are the diagnostics contract). Adding a public member to an enforcing assembly without a `///` doc fails the build on the first compile.
- **`Location` is the site, not the session.** Carries geography (lat/lon/elev/TZ), atmospheric (Bortle/ExtinctionK), and terrain (`LocalHorizon: IHorizonProfile`). It does NOT carry an observation moment, a target floor, or a minimum duration — those are per-session inputs that consumers thread explicitly. As of 2026-05-18 (Phase 2 of the Location refactor), the previously `[Obsolete]` `Horizon`/`Duration` scalars and the `DateTime` field have been removed entirely. Scheduling helpers (`BestSession.For` / `ResolveCandidates` / `SessionSolvers`, `NightCalculator.ComputeNight(location, utc)`, `AltAzCalculator.At(target, location, utc)`) take all per-session inputs as explicit parameters.

### Thread safety

`Astronomy.Core` is **thread-safe by construction** since the CoordinateSharp removal in commit `e602bdb`. Verified: zero *mutable* static fields, zero static caches / dictionaries / `Lazy<T>`, zero ambient-clock reads outside `ObservationMoment.Now`; all static state is **immutable and enumerable** — the four Meeus/Bortle tables, `VisibilityWindows.ProfileScanStep`, and the five canonical singletons the 2026-05-27 sweep introduced (`Location.Default`, `Target.Default`, `MoonLimitProfile.Disabled`/`Narrowband`/`Broadband`). All public APIs take parameters with no hidden state.

**This is a re-runnable audit, not a one-time observation** — re-establish it after any refactor that adds static state (run twice so far: the 2026-05-18 review and its post-refactor recheck, `archive/2026-05-18-library-review-recheck.md`). The recipe: grep `Astronomy.Core` for sync primitives (`lock` / `Interlocked` / `Monitor` / `SemaphoreSlim` / `Mutex` / `SpinLock`), for `[ThreadStatic]` / `ThreadLocal<T>` / `Lazy<T>` / `ConcurrentDictionary`, and for ambient-clock reads — then confirm every remaining `static` field is immutable and individually accounted for. The verdict rests on **naming** the permitted static state, never on asserting there is none; that enumeration is what keeps the claim honest as the set grows. All inputs are immutable POCOs (`Target`, `Location`, `NightWindow`, `MoonLimitProfile`); all returns are immutable POCOs, small structs (`AltAz`, `RiseSetResult` — note `RiseSet` itself is the static helper class, not the value type), or `IReadOnlyList<T>`. **Consumers may call any helper from any thread without external synchronization.**

Two caveats limit that promise:

1. **Caller-supplied delegates are the consumer's responsibility.** Methods that take `Func<...>` parameters — most notably `IntegratedQuality.OverSession(..., Func<double, double> altitudeQuality)` and `IntegratedQuality.HalvesAroundMidpoint(...)`, plus any future delegate-taking helper — invoke the delegate from whatever thread called the method. If a consumer passes a closure that mutates captured state (e.g. `int count = 0; alt => { count++; return ...; }`), thread safety of that closure is on the consumer. Pure / referentially transparent functions are always safe. **The same delegates carry a NaN contract, not just a thread-safety one:** they must return **finite** values across `[-90, 90]`, because a `NaN` or infinite return flows straight into the Simpson sum and silently corrupts the integral — there is no runtime guard. A quality function that rejects below-horizon samples must return `0`, never `double.NaN`.

2. **`Astronomy.PCL` is NOT part of this contract.** PCL is a separate assembly (`Astronomy.PCL.csproj` + `Astronomy.PCL.Native.vcxproj`) wrapping the vendored PixInsight Class Library. `Astronomy.Core` never references it. The underlying PCL C++ library historically isn't safe to call across threads — assume single-threaded access until PCL's own concurrency story is documented per-API.

`NightCache` is a per-`Location` amortization helper: build once per caller planning pass, hand to multiple targets so each target's year work doesn't re-derive the same 365-day `NightWindow` series. The instance is immutable after construction; concurrent readers are safe. Several caches can be built in parallel for different locations.

### Code organization (high-level)

All ten folders, so the map matches the tree:

- `AltAz.cs` / `TargetGeometry.cs` — topocentric coordinate primitives (the core "where is this target right now" math).
- `FieldFootprint.cs` — rotated-rectangle **overlap fraction** on a tangent plane (Sutherland-Hodgman clip + shoelace; exact for convex). RA offsets are scaled by `cos(dec)` — without that, east-west offsets inflate ~2.8× at M81's declination. Pure geometry, no catalog knowledge; `Astronomy.Catalog`'s framing pricing is its caller.
- `Astrometry/` — the provenance core: `Meeus/` (the Meeus-backed algorithm implementations everything else rests on), plus `AstroUtil` (the moon/util entry points; consumes `SiderealTime`), `Refraction` (Saemundsson wrapper over `MeeusUtility`), and the DTOs `ObserverInfo`, `RiseAndSetEvent`.
- `Time/` — `JulianDate` (the central UTC contract gate), `SiderealTime` (GMST/LST), `ObservationMoment`, `TimeKindGuard`.
- `Locations/`, `Targets/` — the immutable observer + target value types described above.
- `Horizons/` — `IHorizonProfile` and four implementations (`Scalar`, `Polyline`, `ObstructionTable`, `MaxOfHorizonProfile`) for flat-vs-azimuth-varying horizon math.
- `Night/` — twilight calculation, `NightWindow` (a single night's astronomical/nautical/civil dusk/dawn), `NightCache` (year-of-nights for one location).
- `Session/` — higher-level analysis built on the primitives: `AltitudeCurve` (uniform-grid sampling via linear LST advance — the speedup over per-sample `AltAzCalculator.At` comes from GMST being linear in UT, so the curve advances LST arithmetically instead of recomputing it; returns `IReadOnlyList<AltAzSample>` with `AltDegGeometric` + `AltDegApparent` + `AzDeg` per sample), `SessionAltitude`, `QualitySamples`, `AltAzSample`, `RiseSet`, `TransitTime`, `VisibilityWindows`, `CoarseVisibility`, `IntegratedQuality`, `BestSession`, `TargetOrdering`, `SessionSolvers`.
- `Sun/` — `SunPosition`, `SunEvents`, `SunPower`, `SunTracking`, `SunSeparation`, `SunHeliographic`.
- `Brightness/` — `SkyBrightness` (Krisciunas–Schaefer), `Bortle`, `Twilight`.
- `Moon/` — **normative spec: `openspec/specs/moon-brightness-gate/`** (the gate's Δmag acceptance semantics, twilight-in-the-moonless-baseline, apparent-altitude convention, `null` ≡ Disabled short-circuit, boundary interpolation, and fail-fast on a below-horizon target are single-sourced there; the *why* behind the tolerance defaults is in `DOMAIN.md`). `MoonSeparation`, `LunarAge`, `MoonLimitProfile` (the K-S Δmag moon gate's parameter POCO — the gate math lives in `Brightness/SkyBrightness.KsMoonDeltaMag`, the walk in `Session/BestSession.MoonClearIntersect`; the gate refracts moon altitude internally while `ObserveAt` stays geometric); `MoonEphemeris.Sample(location, startUtc, step, count)` returns `IReadOnlyList<MoonSample>` with topocentric AltAz (geometric + apparent) + `DistanceKm` + `AgeDays` + `PhaseAngleDeg` + `IlluminatedFrac` per `step`. Pure-function per-night sampling primitive; who consumes it (and the exact-`count` contract) is in `CONSUMERS.md`.

## Astronomy.XISF

- **`Astronomy.XISF`** — `net10.0-windows` (`AnyCPU;x64`, like Core — AnyCPU enables the standalone `dotnet build`), `LangVersion latest`, `Nullable enable`, `ImplicitUsings enable`. XISF (PixInsight image format) read library. Tier 1 surface (2026-05-18) is header-only read: `XisfHeader.cs` (typed FITS-keyword accessors carrying value + comment per keyword) and `XisfHeaderReader.cs` (header-only XISF parser, pure managed `XDocument.Parse()`, no native dep). Since 2026-07-29 the reader also harvests the `<Image>` element's **mandatory `geometry` attribute** (not just `<FITSKeyword>` entries — geometry was present on all 18,650 measured frames while the pixel-dimension keyword duplicates were absent on 63, and the two never disagreed), and `XisfHeader` derives the angular field from those pixel dimensions + `FOCALLEN` + `XPIXSZ`. **No binning multiplier anywhere in that derivation** — `XPIXSZ` is already binning-adjusted, so multiplying would double the field for the 15.8% of the library shot at bin 2. Ported from `XisfFileManager/Files/XisfXmlReader.cs` + a subset of `XisfFileManager/Keyword/KeywordList.cs`. Designed for sharing across XFM, TP, IS, and the user's other apps without dragging NINA's heavyweight `NINA.Image.FileFormat.XISF` (which is coupled to `NINA.Profile` / WPF / image-data factories and forces pixel decode on every read). **Tier 3 (block codecs + verified image read) shipped 2026-08-06/07** — the module is no longer header-only: `Compression/` (`XisfBlockCompression`: symmetric zlib/lz4/lz4hc/zstd ± byte-shuffle, five spec checksum algorithms + legacy-alias canonicalization at `BlockCompressionInfo.Parse`, optional zstd level), `XisfImageReader.ReadImageAsync`, `XisfChecksumVerifier.VerifyAsync`, and `XisfBlockRewriter.RewriteAsync` (byte-preserving surgical block re-store). **Normative specs: `openspec/specs/xisf-block-compression/` + `xisf-image-read/`**; shipped record `CHANGELOG.md` §§ 2026-08-06/07; adopters `CONSUMERS.md` (XFM since v2.4.0). *(Full Tier-3 mechanics are among the promotions held for the ARCHITECTURE split — `docs/2026-08-11-maintain-report.md`.)* Tiers 2 & 4 (metadata write-back, image write) are scoped in `ROADMAP.md` § *Open: Astronomy.XISF Tiers 2 & 4*.
- **`Astronomy.XISF.Tests`** — `net10.0-windows` x64, `OutputType=Exe`. xUnit tests for Astronomy.XISF. Synthetic-XISF fixtures (no test-file dependency), covering header parsing + FITS-value/OFFSET normalization, per-codec round-trips (zlib/lz4/lz4hc/zstd ± shuffle, zstd levels), all five checksum algorithms + the legacy aliases, verified image read, the three-way checksum verdict, and the rewriter's byte-preservation / alignment / corrupt-refusal / temp-hygiene paths.

## Astronomy.Diagnostics

Since 2026-08-10 (`diagnostics-portable-core`) Diagnostics is a **four-assembly layered stack** —
a TFM-neutral core, a Windows capture backend, and per-UI-framework dialog shells. Layering
contract: `openspec/specs/diagnostics-platform-layering/`. Library layers pin the *lowest* TFM
they need (so no consumer is ever forced to raise its own); consumer apps float high — the two
never need to match.

- **`Astronomy.Diagnostics`** — **`net10.0` (TFM-neutral — the one deliberate override of the
  props-level `net10.0-windows` default)**, `Nullable enable`, `ImplicitUsings enable`, zero
  package refs. The portfolio's shared **logging + observation contract** (built 2026-06-11; made
  platform-neutral 2026-08-10 so future non-Windows consumers — an Android app, a Linux host — can
  reference it; a platform API creeping in fails the *build*, which is the enforcement). **Why it
  is its own assembly and not part of `Astronomy.Catalog`:** shared observation tooling stays out
  of Catalog on purpose — Catalog is a schema/build contract, not a grab-bag utility library
  (boundary rule predating Diagnostics itself: `..\TargetSchedulerManager` archive review
  2026-06-10 §4.4; graduated here 2026-08-03). *Convention-as-code*: `Log` (always-on
  Info/Warn/Error severity + gated `Diag` channels — the default comes from
  `AppLogIdentity.DiagDefault`, the build-derived value the app passes to `Init` since a shared
  library compiles once and can't read the consumer's `#if DEBUG`; the app's env var is the
  *override*, read first by `ResolveEnabledCategories`; session rotation; `%APPDATA%\<app>\Logs\`
  structure; USER_OBS protocol — all configured once per app via `AppLogIdentity`).
  `AppLogIdentity.VersionAssembly` (2026-08-10) covers the plugin-host case: a consumer that is a
  guest in another process (IS inside NINA) names its own assembly so the session `build=` stamp
  doesn't report the host's version; null = entry assembly, the standalone-app default.
  **`ObservationSession`** (2026-07-24) is the app-agnostic observation orchestration — id
  minting, START/CAP/END/CANCEL sequencing with the exactly-one-terminator guarantee, capture
  counting, the guarded context-provider call, status-text wording, and the
  hide → settle → grab → reshow choreography (session-level `settleDelayMs`: 450 for WinUI's DWM
  fade, 0 for WinForms' synchronous `Hide()`+`Refresh()`). The shells hand `Begin` **four**
  delegates (owner bounds, hide, show, and — since 2026-08-10 — the platform's `capture`); awaits
  keep the caller's `SynchronizationContext` so the delegates always run on the UI thread.
  `InternalsVisibleTo` exposes the internal ctor (fake capture + path seam) to
  `Astronomy.Diagnostics.Tests`. No `Astronomy.*` deps; pure-managed → builds with `dotnet build`.
- **`Astronomy.Diagnostics.Windows`** — `net10.0-windows` (+ `System.Drawing.Common`), refs core.
  The Windows capture backend: `ScreenCapture.ToPng` (Win32 `Graphics.CopyFromScreen` — grabs the
  literal rendered pixels regardless of UI framework, unlike framework draw-to-bitmap APIs that
  return blank under some compositors). Best-effort: path on success, null on any failure, never a
  throw. This is the platform piece the core deliberately lacks; each future platform supplies its
  own equivalent behind the session's `capture` delegate.
- **`Astronomy.Diagnostics.WinForms`** — `net10.0-windows`, `UseWindowsForms`, refs core +
  `.Windows`. `DiagnosticsDialog`: the WinForms Ctrl+N shell (2026-08-06) — framework glue only
  (Form, controls, singleton focus-existing rule, the session delegates). Consumed by TP and XFM.
- **`Astronomy.Diagnostics.WinUI`** — **`net10.0-windows10.0.19041.0`** (the WinUI *floor*, not
  any app's SDK version), `UseWinUI`, `Microsoft.WindowsAppSDK` (pin recorded in `CONSUMERS.md` —
  WinUI consumers must reference ≥ the pin), refs core + `.Windows`. `DiagnosticsWindow`: the
  WinUI Ctrl+N shell, ported from TSM 2026-08-10 (`ShowOrFocus(owner, contextProvider,
  iconPath?)`; icon caller-supplied; TSM's `UiTask` helper inlined) — same shared dialog
  conventions as the WinForms sibling (Enter=newline, Ctrl+Enter=OK, delayed capture, checkpoint
  notes, singleton). Consumers: TSM (ported 2026-08-10), ISM when built. The
  shells stay unit-test-free by design: testable logic lives in the core session (a WinUI test
  project would force a packaged MSTest host — the standing reason to push logic down instead).
- **`Astronomy.Diagnostics.Tests`** — `net10.0-windows` x64, `OutputType=Exe`, refs core +
  `.Windows`. xUnit v3 tests for the `ObservationSession` state machine (delegate ordering,
  terminator idempotency, mid-countdown cancel, busy-overlap no-ops, status wording), the
  `VersionAssembly` stamp, and `ScreenCapture` smoke coverage (contract-shaped: never-throws +
  PNG-lands-iff-success, so a locked/headless session can't flake it) — against a real `Log`
  pointed at a temp `RootOverride`. The **only** Diagnostics test project — no per-shell test
  projects. Separate from the contract bench because `Log` is process-global and
  `LogLifecycleContractTests` must remain the bench's only **`Log.Init` caller** (it is *not* the
  bench's only `Log` toucher — see the `LogProcessGlobal` rule under *Astronomy.Contracts.Tests*).

## Astronomy.Catalog

- **`Astronomy.Catalog`** — `net10.0-windows` (`AnyCPU;x64`), `LangVersion latest`, `Nullable enable`, `ImplicitUsings enable`. The shared catalog-database library **and** the owner of the .xisf-library scanner. One `Catalog.db` (SQLite via `Microsoft.Data.Sqlite`, plus a **deliberate direct `PackageReference` the code never calls** — `SQLitePCLRaw.bundle_e_sqlite3` 3.0.5, pinned to override the vulnerable native engine 2.1.11 that `Microsoft.Data.Sqlite` 10.0.10 pulls transitively, CVE-2025-6965; there is no 2.1.12, the package renumbered to a 3.x line. It flows to every Catalog consumer and **must not be "cleaned up" as unused**) reconciles two sources onto **one canonical `target`**: the disk image library is **ACTUAL** (source of truth), N.I.N.A. Target Scheduler is the **PLAN**, and the catalog re-organizes the plan clean and anchored to actual. Each `target` carries both facets (disk identity + plan attributes) discriminated by `source_id` — `Actual` (on disk only), `Planned` (in TS only / not yet shot), `Both` (merged); `inventory_filter` (actuals per filter) and `exposure_plan` (goals) both hang off it. Pure-managed → builds with `dotnet build`. **ProjectReferences: `Astronomy.XISF` (the scanner's header reads) and, since 2026-07-29, `Astronomy.Core`** — the framing overlap rule calls `Core.FieldFootprint`, so the sky-geometry sits in the dependency-free base beside the night-window math rather than being duplicated inside a reconciliation namespace. Core is the base of the graph, so the edge is acyclic. Consumers → `CONSUMERS.md`. By folder:
  - **`Scan/`** — the moved `ImageLibraryScanner` + report types (depends on `Astronomy.XISF`), `MosaicConvention`, `FilterPurpose` + `FilterPurposeClassifier`, and the **framing** types (2026-07-29): `FramingCluster` (a unit's (field-center, sky-rotation) group, fold-180 with per-cluster centroid; tolerance constants live here) + internal `FramingClusterer` (expression partition sky/mechanical/unknown → fold-180 gap clustering → field-center single-linkage split, so a pier flip merges and a translated stray separates). The framing cluster is part of the aggregate identity alongside filter/purpose/exposure/gain/offset/binning/camera; mechanical rotation is never converted to sky (remount zero-point drift). A cluster also carries its **footprint** + a spans-sensors flag (dominant sensor when frames span two, never a blend). **Two whole classes of target never enter the scan** — non-sidereal ones (`IsNonSiderealDirectory`; the `"Comet "` prefix is evidence for non-siderealness, not the fact itself, and its **trailing space is load-bearing** — `"Cometary Globule CG4"` and `"NGC 2261 - Comet Nebula"` are sidereal and still scanned) and the `Calibration/` tree. Both are excluded at the directory walk inside `ScanTargetAsync`, one guard serving both entry points, rather than filtered downstream by each consumer. **Scan resilience:** `ScanAsync` runs per-target scans in parallel (`Parallel.ForEachAsync`) and a per-file header-parse failure is **non-fatal** — recorded in `ImageLibraryReport.SkippedFiles`, not aborted on. That is the one deliberate exception to the portfolio's fail-fast-on-contract-violation default (a single unreadable frame must not lose a whole library scan); the surgical `ScanUnitsAsync` path deliberately surfaces no `SkippedFiles`. The tolerance is **per-file only** (2026-08-11): a unit none of whose readable frames carries RA or DEC aborts the scan with `InvalidDataException` naming the directory — coordinates are required for aggregation, and the former silent (0,0) fallback was a real sky position; the scanner never invents one.
  - **`Build/`** — the reconciliation. Anchoring is **scope-equal only**: every resolvable unit carries a coordinate *scope key* — top-level units (and TS targets outside `isMosaic` projects) share the default scope, a panel sits in its mosaic's scope, and a mosaic **parent is in no coordinate scope at all** (name matching *is* its mechanism). A cross-scope match — a panel's goals landing on a sky-overlapping standalone directory — is therefore impossible **by construction**, not filtered out after the fact; that is why the resolver stays one loop instead of growing mosaic branches. `TargetResolver` (pure, **coordinate-primary** — each TS target anchors to the nearest disk target within a tolerance, default 0.5° haversine; an *unaligned* mosaic-panel claim is limited to the tighter `PanelMatchToleranceDegrees`, default 0.1° — a name-aligned panel directory anchors at the full tolerance since the name confirms identity, while a merely-nearby unrelated framing stays unclaimed; name only validates; **name alignment also gates a second, separate mechanism — a post-anchor *outranking* pass**: when one disk unit accumulates several TS claims and at least one is name-aligned, every unaligned claim is *released* back to unanchored (it applies to any unit, not just panels, and runs before name-validation reporting so released claims don't also flag). The rule **only ever demotes, never invents** — with no aligned claim at all, the nearest unaligned match stands and is flagged. This is what keeps an unshot panel inside tolerance of a shot neighbour classified `Planned` instead of false-folding onto it, and it decides whether a TS row lands in `UnanchoredTsTarget` vs `AmbiguousMatch`; disk plate-solved coords win on merge; the TS guid is **retained on `Both` for write-back**; TS duplicates fold onto one canonical and name-mismatch / ambiguous / unanchored / out-of-range rows are reported in `CatalogBuildReport` — typed rows `NameMismatch` / `AmbiguousMatch` / `UnanchoredTsTarget` / `InvalidTsTarget` / `DuplicateTsTarget` — not dropped). **Harden rule:** never pass a raw TS integer into a CHECK/FK column — `TargetResolver` coerces unknown epoch/state/priority codes to a safe default and normalizes/clamps planned RA/Dec, so a single bad external TS row can't abort the rebuild. `CatalogBuilder.BuildAsync` is the full rebuild: scan disk + read TS → resolve → `WriteCatalog` in one transaction; either source may be omitted.
  - **`Schema/`** — the POCOs/mappers + `schema.sql`. (`SchemaManager`, `CatalogStore`, `GuidBlob` and the `Data/` mapper plumbing — `ITableMapper`, `SqliteReaderExtensions` — live at project root / `Data/`.) `SchemaManager` applies `schema.sql` idempotently — **no migration framework**: the catalog is fully derived (scan + TS import) and rebuildable, so a schema change just means deleting `Catalog.db`. `CatalogStore` is the read/write surface: `WriteCatalog(graph)` replaces the whole catalog transactionally; `GetShotTargets()` = source `Actual`|`Both` **and `parent_target_id IS NULL`** is the actual-only view — a `Both` target has frames on disk, so it belongs; planned-only is excluded, and so is every mosaic *panel* child even when it has frames, since the query returns only the parent grouping node — descend with `GetChildTargets(parentId)`. **A mosaic is modelled as a parent target plus one child target per panel** (`target.parent_target_id`, indexed `ix_target_parent`); that hierarchy is what per-panel write-back and panel-radius gating operate on.
  - **`TargetScheduler/`** — `TargetSchedulerReader` reads TS's `schedulerdb.sqlite` read-only (Mode=ReadOnly + busy-timeout, explicit columns). `TargetSchedulerWriter` (+ pure `WriteBackPlanner` / `SingleTargetPlanner`) writes reconciled disk counts back into a **local** TS copy (Phase 4 engine — bulk or surgical single-target, per panel for mosaics; column-presence-validated, read-back verified; returns `WriteBackResult` with `WriteBackChange` / `WriteBackVerifyFailure` rows). On the write-back side a multi-claimed cell is *withheld* rather than merely reported: `WriteBackPlanner` holds it out of the auto-write plan as a `ManualGroup` carrying a structured `ManualReason` (`MultiPlan` / `DuplicateFold` / `IdentityConflict` / `NoMatchingPlan`) plus the competing `ManualPlan` rows for hand resolution, with `ReconcileNote` / `UnplannedFrames` for the no-plan case; consumers render that hold-back surface. (The alias-fold escape that used to auto-write ex-alias multi-claims was removed 2026-07-23.) Write-back groups plans on the four-part key **(target, filter, purpose, whole-second exposure)** and, within the bucket, **credits only frames whose capture configuration pairs with the plan's template** (2026-08-04, `pairing-credited-write-back`): `CaptureConfigPairing` is the single gain/offset/binning predicate (value equality after plan-side normalization; the camera-default sentinel `-1` pairs with nothing), shared by `ReconciliationProjection`'s cell key, `WriteBackPlanner`'s credit sum, and `SingleTargetPlanner`'s cell routing — never folded across durations or configurations (contract statement + the zero-is-a-real-write corollary → `CONSUMERS.md` § *Contract facts not yet numbered*). **Write-back likewise credits only frames whose framing serves the plan** (2026-07-29): `FramingCluster.ServesPlanRotation` is the single rotation-participation predicate, shared by the same three call sites — so the consumer's badge and the stamped counts can never tell different stories. A non-serving disk framing is **excluded from the count entirely** (bulk *and* surgical), not merely flagged: a re-framed plan stamps its true progress, possibly 0, and a withheld surgical cell emits a `FramingMismatch` note naming the frames, the framing, and the rotation they fail. Mechanical/unknown framings and rotation-less targets always credit; fold-180 flips still credit. **Dry-run is supported but not a default** — `Execute(WriteBackPlan plan, bool apply)` takes `apply` as a required argument, so every caller states intent explicitly; the "default" belonged to the `--apply`-off CLI verbs, which retired with the consumer's console host 2026-06-11, to resurface as a TSM app action.
  - **`Reconcile/`** — goal-vs-actual. `Reconciler` + `CatalogStore.GetReconciliation`: TS goals (`exposure_plan.desired_count`) vs disk actuals (`inventory_filter`) per (target, filter), joined on the shared single-letter filter name — actuals are disk truth (TS's stale `acquired_count` is ignored). `ReconcilePolicy.Combined` (default) counts Light + Stars toward a goal; status is NotStarted/InProgress/Complete/Unplanned. `ReconciliationProjection.Project(graph, report)` flattens the graph into per-target `TargetCells` / `ReconciliationCell` rows — the grid-shaped projection consumers bind directly. Its cell key is the capture configuration **plus the framing cluster** (2026-07-29): a plan pairs with the disk framing whose sky rotation agrees fold-180 with the target's rotation; mechanical/unknown framings and rotation-less targets skip the rotation term (it never prevents pairing), and a disk cell whose sky rotation fails the plan carries `FramingDisagrees` for the consumer's badge. An off-footprint framing is also **priced, not just flagged**: the overlap fraction is the share of the framing's own footprint landing inside the plan's rectangle, measured against **that framing's own dominant sensor** (never a neighbouring framing's), via `Astronomy.Core.FieldFootprint`. A serving framing prices nothing while it stays at or above `FramingCluster.OnFootprintFraction` (0.95); a disagreeing one always reports whatever its overlap, so a badge is never left pointing at an empty cell. The fraction means off-footprint for *any* reason — wrong rotation, wrong pointing, or both — and crediting stays the boolean `ServesPlanRotation`: a partially overlapping frame is not a fractional frame.

### PCL interop

The hybrid architecture from `archive/PCL-InterOp.md` (the archived interop-rationale decision record) is **implemented** for the first surface (XISF read). Two projects:

- `Astronomy.PCL.Native` (C++ DLL, statically links PCL `.lib`s from `Library\PCL\lib\x64\`).
- `Astronomy.PCL` (managed P/Invoke wrapper, `net10.0-windows` x64).

C ABI is the source of truth: `Astronomy.PCL.Native\include\Astronomy\PCL\XisfCApi.h`. Every **fallible** export is wrapped in `ASTRONOMY_PCL_TRY` / `ASTRONOMY_PCL_CATCH` (in `src\Exception.h`) — this catches `pcl::Exception` and `std::exception` and translates to status codes; the `catch (...)` branch picks up SEH (access violations etc.) due to `<ExceptionHandling>Async</ExceptionHandling>`. Two exports are deliberately bare: `AstronomyXisf_Ping`, and `AstronomyXisf_GetLastErrorMessage` — the latter **must never** use the macro, because the CATCH body calls `SetLastError` and would clobber the very thread-local it exists to read. Last-error message is thread-local (`src\LastError.cpp`); consumers retrieve via `AstronomyXisf_GetLastErrorMessage` (two-call idiom: query length, alloc, fetch).

Two more host-process survival mechanisms keep PCL from touching the nonexistent PixInsight platform: `SilentLogHandler` (`src\SilentLogHandler.h`, a no-op `pcl::XISFLogHandler` installed on every reader so PCL logging never reaches a nonexistent console) and a file-static `PclRuntimeInit` ctor (`XisfCApi.cpp`) that runs at DLL load and calls `pcl::Exception::DisableGUIOutput()` / `DisableConsoleOutput()` — without it an exception's *destructor* tries to write to the PixInsight GUI console and surfaces as an unrecognized exception type at the catch sites.

**Watch-out: don't use `XISFReader::ReadImage(FImage&)` for non-float source images.** PCL's auto-converting read path appears to need PixInsight platform services that aren't available in a host process — UInt16 or UInt32 sources surface as an unrecognized SEH exception ("Unknown C++ exception" at `catch (...)`). The wrapper dispatches on `ImageOptions.bitsPerSample` / `ieeefpSampleFormat`, reads in the file's native type (`UInt16Image`, `FImage`, `DImage`, …), then converts to float32 in our own loop. See `XisfCApi.cpp:AstronomyXisf_ReadImageF32`.

Adding new PCL surfaces: bind on demand — **and preserve the standing convention that pixel I/O is explicit.** `Open` / `SelectImage` / `GetImageInfo` never read pixel data (metadata costs milliseconds; one `ReadImage` on a 5496×3672 frame costs hundreds of ms and ~80 MB), so a caller pays for pixels only where it asks for them. Any new surface must keep that split rather than quietly decoding on a metadata call. Add the `extern "C"` export to `XisfCApi.h` and `Astronomy.PCL.Native.def`, implement in `XisfCApi.cpp` wrapped in the macro (unless it's an error/diagnostic-retrieval export — see the `GetLastErrorMessage` exception above), mirror the `[DllImport]` in `Astronomy.PCL/Interop/NativeMethods.cs`, expose the C# surface in `Astronomy.PCL`. Test in `Astronomy.Core.Tests/Tests/PCL/`.
